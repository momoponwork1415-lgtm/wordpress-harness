WordPress pluginのsourceを、探索可能な「根拠状態付きの攻撃面」へ変換するartifact。 完全なcall graphでも、脆弱性の判定結果でもない。

2 / Evidence, not confidence

各claimは「どの程度分かっているか」を持つ

modelの自信ではなく、再確認できる根拠で区別する。誤差を消すのではなく、観測・推論・未解決を混ぜない。

observed

sourceから直接観測

  • file digestとbyte range
  • parserが抽出したsymbolやWordPress fact
  • modelは変更・削除できない
inferred

根拠から導いたclaim

  • premiseを必ず保持
  • deterministic / knowledge / model
  • observedとは別の状態
unknown

未解決を明示

  • 候補と曖昧な理由
  • 次に必要な証拠
  • 到達可能なedgeとして扱わない
entry REST route / hook
→
symbol callback function
⇢
source・guard・state・sink 探索でrouteを組み立てる材料

現行sliceは決定論的な dispatches-to と、検査済みの model提案から flows-to を構築する。model失敗は mapping-incomplete gapとして残る。

3 / Script + AI + Verification

決定論的な骨格をAIが補完し、検証は別Moduleが行う

すべてを静的scriptで解こうとしない。一方で、AIの直接出力をMapにせず、検査済みの差分だけを次revisionへ入れる。

Deterministic Source Mapping

  • Target identityと全file inventory
  • parser factとsource anchor
  • 一意なliteral callback relation
  • stable ID・順序・CAS revision

AI Mapper

  • Context path + 1-hop Map subgraph
  • feature境界とcross-file relation候補
  • dynamic dispatchの候補
  • stateを跨ぐroute候補
  • 追加のContext Request
AIは observed を上書きしない。追加できるのは根拠付きの inferred または理由付きの unknown。
現在の実装は既存node間の flows-to 提案、Delta Receipt、失敗gapまで。追加node・Conflict・Context Request・repair・tool付きMapperは次のsliceである。
