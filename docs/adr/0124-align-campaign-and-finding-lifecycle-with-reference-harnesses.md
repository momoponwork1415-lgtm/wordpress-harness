# Let Independent Validation create Findings

Independent Validation, not a Finder, may create an immutable source-validated Finding. Fresh AI runtime verification and optional fresh human verification add append-only Verification Records without recreating or deleting the Finding. A runtime contradiction may mark a Finding disproved, while provider, budget, setup, or ambiguous runtime outcomes remain incomplete rather than negative. Finding existence and Coverage Closure remain independent.

The mandatory human gate moves from Finding creation to external action. Duplicate comparison, analysis, and draft generation may run before human confirmation. Form staging, vendor contact, submission, and publication require an External Action Authorization bound to the exact draft revision and destination.

This decision does not replace the current Semantic Research Wave, conditional Depth, or Closure design, and it does not introduce a new public orchestration Interface. Those changes require separate evidence and a separate design gate after one end-to-end pilot. Existing Runtime Verification Packet, Triage Reproduction Packet, and human-only Finding writers remain current until the new lifecycle vertical slice is proven; afterward they may be retained only for read-only replay.

This replaces ADR 0123 because that decision made a mandatory fresh human reproduction the only path to a Finding. The new lifecycle aligns the term Finding with reference harnesses while preserving WordPress specialization and prospective oracle separation.
