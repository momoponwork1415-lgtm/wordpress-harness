# ドキュメント案内

**コードを変更するなら、[コードベース案内](CODEBASE-GUIDE.md)で担当モジュールを選び、そのInterfaceとBehavior Testへ進む。** 全文書の通読は不要です。

## 読む目的から選ぶ

| 知りたいこと | 入口 |
| --- | --- |
| 全体の責務と受け渡し | [全体構成](ARCHITECTURE.md) — 3領域の関係を1枚で見る |
| 一件の処理順と人間の判断点 | [処理の流れ](SYSTEM-WALKTHROUGH.md) |
| 変更箇所・契約・テスト・未接続箇所 | [コードベース案内](CODEBASE-GUIDE.md) |
| 探索・停止・候補検証の設計原則 | [探索設計](RESEARCH-DESIGN.md) |
| 用語の意味 | [領域の対応表](../CONTEXT-MAP.md)から担当領域の用語集へ |
| 次の有限作業と受入条件 | [GitHub Issues](https://github.com/momoponwork1415-lgtm/wordpress-harness/issues) |

一般的な説明には日本語を使います。`CampaignInput`のような契約名、`continue` / `stop`のような実際の値、CLI、ADRなど、コードや外部仕様と照合する必要がある語だけ英語のまま残します。

## 情報の正本

正本を持つとは、すべてを一文書へ集めることではなく、**同じ事実の更新先を一つにすること**です。

| 更新する情報 | 正本 | 他の場所での扱い |
| --- | --- | --- |
| 開発規則 | [AGENTS.md](../AGENTS.md) | 規則を複製せず参照する |
| 領域の責務・受け渡し・用語 | [領域の対応表](../CONTEXT-MAP.md)と各用語集 | 全体構成では関係だけを図示する |
| 目的・探索方針・安全上の不変条件 | [探索設計](RESEARCH-DESIGN.md) | コードベース案内は担当モジュールと回帰テストへ案内する |
| 現在のモジュール・Interface・実装状態・ソース・Behavior Test対応 | [コードベース案内](CODEBASE-GUIDE.md) | 概要図や処理の流れへ実装状況を書かない |
| schemaの正確なfield・定数・実行可能な動作 | コードベース案内から辿るソースとBehavior Tests | 型定義やプロバイダー設定値を文章へ転記しない |
| 後戻りしにくい判断の理由 | 対応する[ADR](adr/) | 必要な設計節からだけ参照する |
| 実測・外部資料の調査 | [調査資料](knowledge/) | 通常の読む順から外す |
| 未完了作業・受入条件 | GitHub Issues | 図に「次に作るもの」を並べない |

図は正本から導く説明用の表示です。全体図は責務と受け渡し、処理順の図は人間の判断点と戻り先だけを示します。契約の詳細はコードベース案内へ進みます。

完了済みの計画、旧設計、過去の状態はGit履歴から読みます。非公開の対象、payload、実行記録、認証情報、未公開の発見事項はドキュメントへ入れません。
